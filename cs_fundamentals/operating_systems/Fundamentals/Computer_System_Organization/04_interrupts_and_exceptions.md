# Interrupts and Exceptions

## Overview

**Interrupts** and **exceptions** are mechanisms that allow the CPU to respond to events that require immediate attention. They transfer control from currently executing code to special handler routines.

## Definitions

### Interrupt
**Definition**: An asynchronous signal from hardware indicating an event that needs immediate attention.

**Characteristics**:
- **Asynchronous**: Can occur at any time, independent of current instruction
- **External**: Generated by hardware devices (keyboard, disk, timer, network card)
- **Resumable**: Interrupted program continues after handling

### Exception
**Definition**: A synchronous event caused by the execution of an instruction.

**Characteristics**:
- **Synchronous**: Occurs during instruction execution
- **Internal**: Generated by CPU detecting an error or special condition
- **May be resumable**: Depends on exception type

## Interrupt vs Exception

```
┌──────────────────────────────────────────────────────────┐
│                    CPU Events                            │
├──────────────────┬───────────────────────────────────────┤
│   INTERRUPTS     │         EXCEPTIONS                    │
├──────────────────┼───────────────────────────────────────┤
│ - Asynchronous   │ - Synchronous                         │
│ - Hardware       │ - Software/CPU                        │
│ - I/O devices    │ - Errors or traps                     │
│ - Timer          │ - Page fault, divide-by-zero          │
│ - Network        │ - System calls                        │
│ - Keyboard       │ - Illegal instruction                 │
└──────────────────┴───────────────────────────────────────┘
```

## Types of Interrupts

### 1. Hardware Interrupts

**Maskable Interrupts**:
- Can be disabled/enabled by CPU
- Non-critical events
- Examples: keyboard, mouse, disk I/O

**Non-Maskable Interrupts (NMI)**:
- Cannot be disabled
- Critical events requiring immediate attention
- Examples: hardware failure, memory errors, power failure

### 2. Software Interrupts

**System Calls (Traps)**:
- Intentional interrupts triggered by software
- Used to request OS services
- Example: `int 0x80` (Linux x86), `syscall` (x86_64)

**Example (x86 Assembly)**:
```asm
; Linux system call - write to stdout
mov rax, 1          ; System call number (write)
mov rdi, 1          ; File descriptor (stdout)
mov rsi, message    ; Buffer address
mov rdx, 13         ; Message length
syscall             ; Trigger software interrupt
```

### 3. Timer Interrupts

**Purpose**:
- Implement time-sharing
- Update system clock
- Enforce CPU time limits
- Schedule periodic tasks

**Frequency**: Typically 100-1000 Hz (every 1-10 ms)

**Example (Conceptual)**:
```c
void timer_interrupt_handler() {
    // Update system time
    system_ticks++;
    current_time = system_ticks / TIMER_FREQUENCY;

    // Update process time
    current_process->cpu_time++;

    // Check if time slice expired
    if (current_process->cpu_time >= TIME_SLICE) {
        schedule_next_process();
    }
}
```

## Interrupt Handling Mechanism

### Interrupt Handling Steps

```
1. Device generates interrupt signal
         ↓
2. CPU finishes current instruction
         ↓
3. CPU checks interrupt pending
         ↓
4. Save current state (PC, registers)
         ↓
5. Disable interrupts (optional)
         ↓
6. Determine interrupt source (vector)
         ↓
7. Call Interrupt Service Routine (ISR)
         ↓
8. Execute ISR
         ↓
9. Restore saved state
         ↓
10. Re-enable interrupts
         ↓
11. Resume interrupted program
```

### Interrupt Vector Table (IVT)

**Definition**: Table mapping interrupt numbers to handler addresses.

**x86 Interrupt Vector Table**:
```
┌──────┬─────────────────────────────────────┐
│ Vec  │  Handler Description                │
├──────┼─────────────────────────────────────┤
│  0   │  Divide by Zero                     │
│  1   │  Debug                              │
│  2   │  Non-Maskable Interrupt             │
│  3   │  Breakpoint                         │
│  4   │  Overflow                           │
│  5   │  Bound Range Exceeded               │
│  6   │  Invalid Opcode                     │
│  7   │  Device Not Available               │
│  8   │  Double Fault                       │
│ ...  │  ...                                │
│  13  │  General Protection Fault           │
│  14  │  Page Fault                         │
│ ...  │  ...                                │
│  32  │  Timer Interrupt (IRQ 0)            │
│  33  │  Keyboard Interrupt (IRQ 1)         │
│ ...  │  ...                                │
│  255 │  User-defined                       │
└──────┴─────────────────────────────────────┘
```

**Structure**:
```c
typedef struct {
    uint32_t offset_low;    // Lower 16 bits of handler address
    uint16_t selector;      // Code segment selector
    uint8_t  zero;          // Reserved
    uint8_t  type_attr;     // Type and attributes
    uint32_t offset_high;   // Upper 16 bits of handler address
} IDT_Entry;

IDT_Entry interrupt_descriptor_table[256];
```

### Context Switching During Interrupt

**State Saved by Hardware**:
```
┌─────────────────────┐
│  EFLAGS/RFLAGS     │  Status flags
│  CS (Code Segment) │  Code segment
│  EIP/RIP           │  Instruction pointer
└─────────────────────┘
```

**Additional State Saved by Software (ISR)**:
```c
void interrupt_handler() {
    // Save general-purpose registers
    __asm__ volatile (
        "push %rax\n"
        "push %rbx\n"
        "push %rcx\n"
        "push %rdx\n"
        "push %rsi\n"
        "push %rdi\n"
        "push %rbp\n"
        "push %r8\n"
        "push %r9\n"
        "push %r10\n"
        "push %r11\n"
        "push %r12\n"
        "push %r13\n"
        "push %r14\n"
        "push %r15\n"
    );

    // Handle interrupt
    handle_interrupt();

    // Restore registers
    __asm__ volatile (
        "pop %r15\n"
        "pop %r14\n"
        // ... (in reverse order)
        "pop %rax\n"
    );
}
```

## Types of Exceptions

### 1. Faults

**Characteristics**:
- Correctable errors
- Reported before faulting instruction
- Can be resumed after correction
- EIP points to faulting instruction

**Examples**:
- **Page Fault**: Accessing non-resident page
- **Segment Fault**: Accessing invalid memory segment
- **Division by Zero**: Attempting to divide by zero

**Page Fault Handler (Conceptual)**:
```c
void page_fault_handler(uint32_t error_code, uint32_t faulting_address) {
    // Check if page is in swap space
    if (is_page_swapped(faulting_address)) {
        // Load page from disk
        load_page_from_disk(faulting_address);

        // Update page table
        update_page_table(faulting_address, PRESENT);

        // Resume execution (retry faulting instruction)
        return;
    } else {
        // Invalid access - terminate process
        segmentation_fault();
    }
}
```

**Example (C - Triggering Page Fault)**:
```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    // Allocate but don't use (lazy allocation)
    char *memory = (char *)malloc(1024 * 1024 * 1024); // 1 GB

    // First access causes page fault
    memory[0] = 'A';  // Page fault → OS allocates physical page

    // Subsequent accesses to same page are fast
    memory[1] = 'B';  // No page fault

    free(memory);
    return 0;
}
```

### 2. Traps

**Characteristics**:
- Intentional exceptions
- Reported after trap instruction
- Used for system calls and debugging
- EIP points to next instruction

**Examples**:
- **System calls**: `syscall`, `int 0x80`
- **Breakpoints**: `int 3` (debugger)

**System Call Example (C)**:
```c
// User code
int fd = open("/tmp/file.txt", O_RDONLY);

// Compiled to:
// mov rax, 2       ; syscall number for open
// mov rdi, filename
// mov rsi, O_RDONLY
// syscall          ; Trap to kernel

// Kernel trap handler:
void syscall_handler() {
    // Read syscall number from RAX
    int syscall_num = get_register(RAX);

    // Dispatch to appropriate handler
    switch (syscall_num) {
        case 2:  // open
            sys_open();
            break;
        // ... other syscalls
    }
}
```

### 3. Aborts

**Characteristics**:
- Serious, unrecoverable errors
- Cannot resume execution
- Process typically terminated

**Examples**:
- **Double Fault**: Exception during exception handling
- **Machine Check**: Hardware error detected
- **Invalid TSS**: Task State Segment corruption

**Example (Conceptual)**:
```c
void double_fault_handler() {
    printk(KERN_EMERG "KERNEL PANIC: Double Fault\n");
    print_registers();
    print_stack_trace();

    // Cannot recover - halt system
    for (;;) {
        halt();
    }
}
```

## Interrupt Priority and Nesting

### Priority Levels

```
┌─────────────────────────────────────┐
│  Priority (High to Low)             │
├─────────────────────────────────────┤
│  1. Non-Maskable Interrupt (NMI)    │  Highest
│  2. Machine Check Exception         │
│  3. Timer Interrupt                 │
│  4. Disk I/O Interrupt              │
│  5. Network Interrupt               │
│  6. Keyboard Interrupt              │  Lowest
└─────────────────────────────────────┘
```

### Nested Interrupts

**Scenario**: Higher priority interrupt arrives during ISR execution.

**Example**:
```c
void low_priority_isr() {
    enable_interrupts();  // Allow higher priority interrupts

    // Do work
    process_network_packet();

    // If timer interrupt arrives here, it will preempt
    // and will be handled immediately

    disable_interrupts();
    // Finish critical section
}
```

**Nested Interrupt Timeline**:
```
Main Program
    ↓
Keyboard Interrupt (Low Priority)
    ↓
    ISR processing...
        ↓
        Timer Interrupt (High Priority)
            ↓
            ISR processing...
            ↓
        Return from Timer ISR
        ↓
    Continue Keyboard ISR
    ↓
Return to Main Program
```

## Interrupt Latency

**Definition**: Time from interrupt occurrence to start of ISR execution.

**Components**:
```
Total Latency = Interrupt Detection Time +
                Context Save Time +
                ISR Dispatch Time
```

**Typical Values**:
- **Detection**: 1-10 CPU cycles
- **Context Save**: 20-100 CPU cycles
- **Dispatch**: 10-50 CPU cycles

**Total**: Microseconds on modern CPUs

**Reducing Latency**:
1. **Minimize ISR work**: Defer non-critical work
2. **Use interrupt priorities**: Handle critical interrupts first
3. **Optimize context save**: Save only necessary registers
4. **Disable interrupts sparingly**: Keep critical sections short

## Deferred Interrupt Handling

### Two-Level Interrupt Handling

**Top Half (Hard IRQ)**:
- Runs with interrupts disabled
- Minimal processing
- Acknowledges interrupt
- Schedules bottom half

**Bottom Half (Soft IRQ)**:
- Runs with interrupts enabled
- Heavy processing
- Can be preempted

**Example (Linux Kernel Concept)**:
```c
// Top Half - Hard IRQ Handler
irqreturn_t network_irq_handler(int irq, void *dev_id) {
    // Minimal work with interrupts disabled

    // Acknowledge hardware
    ack_network_interrupt();

    // Read packet header
    packet_header = read_packet_header();

    // Schedule bottom half
    schedule_work(&network_bottom_half);

    return IRQ_HANDLED;
}

// Bottom Half - Workqueue
void network_bottom_half(struct work_struct *work) {
    // Heavy processing with interrupts enabled

    // Read full packet
    packet = read_full_packet();

    // Process packet (can take time)
    process_packet(packet);

    // Update statistics
    update_network_stats();
}
```

**Benefits**:
- Minimizes interrupt latency
- Allows interrupt nesting
- Better system responsiveness

## Interrupt Masking

### Disabling Interrupts

**C Example**:
```c
void critical_section() {
    // Disable interrupts
    unsigned long flags;
    local_irq_save(flags);

    // Critical code - no interrupts
    shared_data++;

    // Re-enable interrupts
    local_irq_restore(flags);
}
```

**Assembly Example (x86)**:
```asm
cli     ; Clear interrupt flag (disable)
; Critical section
sti     ; Set interrupt flag (enable)
```

### Selective Masking

**Mask specific interrupts**:
```c
void mask_keyboard_interrupt() {
    uint8_t mask = inb(0x21);  // Read interrupt mask register
    mask |= 0x02;               // Set bit 1 (keyboard)
    outb(0x21, mask);          // Write back
}

void unmask_keyboard_interrupt() {
    uint8_t mask = inb(0x21);
    mask &= ~0x02;              // Clear bit 1
    outb(0x21, mask);
}
```

## Real-World Examples

### Linux Interrupt Handling

**Register Interrupt Handler**:
```c
#include <linux/interrupt.h>

static irqreturn_t my_interrupt_handler(int irq, void *dev_id) {
    // Handle interrupt
    printk(KERN_INFO "Interrupt received!\n");
    return IRQ_HANDLED;
}

int init_module(void) {
    // Request IRQ line
    int result = request_irq(IRQ_NUMBER,
                             my_interrupt_handler,
                             IRQF_SHARED,
                             "my_device",
                             NULL);
    return result;
}
```

### Handling Page Faults (Java)**:
```java
public class PageFaultDemo {
    public static void main(String[] args) {
        try {
            // Allocate large array
            byte[] data = new byte[1024 * 1024 * 1024]; // 1 GB

            // First access may cause page fault (OS handles transparently)
            data[0] = 1;

            // Process continues normally
            System.out.println("Array allocated successfully");

        } catch (OutOfMemoryError e) {
            // OS couldn't handle page fault (no memory)
            System.err.println("Out of memory");
        }
    }
}
```

### JavaScript Event Loop (Conceptual Similarity)

```javascript
// Similar concept to interrupt-driven I/O

// Register "interrupt handler" (event listener)
document.addEventListener('click', function(event) {
    console.log('Click interrupt handled');
});

// Main program continues (not blocked)
console.log('Main program running');

// When click occurs:
// 1. Event queued (like interrupt pending)
// 2. Event loop dispatches to handler (like ISR)
// 3. Handler executes
// 4. Returns to event loop
```

## Key Takeaways

1. **Interrupts are asynchronous** (hardware), **exceptions are synchronous** (software/CPU)
2. **Interrupt handling** involves saving context, executing ISR, and restoring context
3. **Interrupt Vector Table (IVT)** maps interrupt numbers to handler addresses
4. **Three exception types**: Faults (correctable), Traps (intentional), Aborts (fatal)
5. **Two-level handling** (top/bottom half) minimizes interrupt latency
6. **Priority and nesting** allow critical interrupts to preempt less important ones
7. **Disabling interrupts** protects critical sections but increases latency
